# 請假登記表：專案規則

本資料夾是「請假登記表」示範系統。動手前先讀 `需求筆記.txt`。
本檔案的規則適用於 `請假登記表/` 資料夾內的所有工作；儲存庫根目錄的 `AGENTS.md` 是報修系統的規則，兩者不要混用。

## 每次開工

- 開工前一定先更新到 GitHub 上最新的 `main`，再從 `main` 開工作分支。不要在舊版本上繼續改。
- 讀過 `需求筆記.txt`，確認這次的工作對應哪一段需求。

## 金鑰與機密（最重要）

- 前端只能使用 Supabase 的 **publishable key**（公開金鑰，開頭為 `sb_publishable_`）。
- **secret key（開頭為 `sb_secret_`）與舊版 service_role key 不可以寫進任何檔案**，包括程式碼、設定檔、SQL、文件、註解、測試資料與 commit 訊息。
- 不把任何密碼、權杖或私鑰放進儲存庫。發現已經被提交時，立刻停下來告訴使用者，不要自己改寫存檔紀錄。
- 資料安全靠資料庫的 GRANT 與 RLS，不靠隱藏金鑰。

## 資料與用語

- 只使用虛構的姓名、部門與事由，不放真實姓名、員工編號或客戶資料。
- 使用者看到的文字一律用繁體中文。
- 假別、審核狀態的選項必須和 `需求筆記.txt` 一致：
  - 假別：特休、事假、病假、補休、公假、婚假、喪假、其他
  - 審核狀態：待審核、已核准、已退回
- 需求筆記沒寫到的地方標「待確認」，不要自己假設後當成定案。

## 資料庫規則

- 新資料表必須啟用 RLS，並明確寫出 GRANT；不能依賴預設權限。
- 同仁只能新增與讀取自己的紀錄，新增時狀態只能是「待審核」。
- 只有主管能讀取全部紀錄，並且只能修改審核狀態。
- 沒有人可以刪除紀錄。
- SQL 檔案只產生、不執行，除非使用者明確要求。

## 建議的檔案位置

- 網頁前端：`請假登記表/` 內的 `index.html`、`style.css`、`app.js`、`config.js`
- 資料庫：`請假登記表/supabase/`
- Excel、簡報、Word 等文件：`請假登記表/文件/`

## 完成之後

- 用清楚的繁體中文 commit 訊息，例如「新增請假表單」。
- 完成後用 GitHub 外掛建立 Pull Request，並合併進 `main`。
- Pull Request 說明要寫：改了什麼、對應哪一段需求、做了哪些驗證；有畫面變更時附截圖。
- 沒有實際測試過的部分，要在 Pull Request 和回報中寫清楚。
